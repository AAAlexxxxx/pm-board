# Облачный дэшборд Polymarket: дизайн (2026-09-27)

Цель: тот же экран поиска рынков и бумажной торговли, что и локальное приложение (`paper-live`), но живущий
в GitHub и открывающийся на iPhone как страница Safari → «На экран Домой» (PWA). Ноутбук больше не нужен.

## 1. Архитектура: «сервер без сервера»

```
                GitHub Actions (cron / кнопка / dispatch с телефона)
                ┌──────────────────────────────────────────────────────────┐
Gamma / CLOB ──►│ python -m pmcloud refresh|cycle|trade                    │
 (публичные API)│   1. снимок всех открытых рынков (7д объём ≥ $1k)        │
                │   2. отметка и погашение позиций обеих книг               │
                │   3. fair value по калибровке для всех ликвидных фаворитов│
                │   4. аномалии (скачки, всплески, слом фаворита, neg-risk) │
                │   5. [cycle] движок Claude: скан 72ч, сделки core/explore │
                │   6. [trade] ручная сделка книги A по живому стакану      │
                │   7. cloud/site/data/*.json  +  commit cloud/state/*      │
                └──────────────┬───────────────────────────────────────────┘
                               ▼  deploy-pages
                     GitHub Pages: cloud/site (статика + PWA)
                               ▼
                iPhone Safari / иконка на экране «Домой»
                  (POST api.github.com/…/dispatches с личным токеном → сделка / обновить сейчас)
```

| Слой | Где | Что |
|---|---|---|
| Состояние | `cloud/state/` в git | `book.json` (ручная книга A), `book_claude.json` (движок, книга B), `calibration.json`, `nav_history.jsonl`, `claude_log.jsonl`, `claude_shadow.jsonl`, `alerts.jsonl`, `prev_mids.json`, `mid_days.json`, `last_action.json` |
| Бэкенд | `cloud/backend/pmcloud/` | Python 3.12, только `requests`/`pandas`/`numpy`; порт `pmtrader.markets/trade` и `engine/live_bot.py` без локальных путей |
| Планировщик | `.github/workflows/pmcloud.yml` | cron: каждые 30 минут `refresh`, раз в день `cycle` (10:05 UTC, как локальный `claude_cycle.cmd`); `repository_dispatch` с телефона: `refresh`, `cycle`, `scan`, `trade` |
| Фронтенд | `cloud/site/` | один `index.html` + `app.js` + `style.css`, без сборки; `manifest.webmanifest`, `sw.js`, иконки; данные из `data/*.json` |

Почему так: публичные API Polymarket не требуют ключей, вся «торговля» бумажная, состояние маленькое (десятки КБ) —
git как база данных достаточен, а GitHub Pages бесплатен и не засыпает. Лимит Actions (2000 мин/мес на приватном репо):
hourly refresh ≈ 2 мин × 24 × 30 = 1440 мин — укладывается; на публичном репо лимита нет и можно ставить `*/15`.
Сайт на Pages из приватного репо всё равно публичный (кроме Enterprise) — секретов в нём нет, токен живёт только в телефоне.

## 2. Данные для страницы (`cloud/site/data/`)

| Файл | Содержимое | Размер |
|---|---|---|
| `meta.json` | время снимка, число рынков, режим последнего запуска, результат последней команды с телефона | 1 КБ |
| `markets.json` | компактные строки рынков: вопрос, событие, категория, bid/ask Yes, объёмы, дни до конца, fee, fair value / edge / ann. edge по калибровке | ~1.5 МБ (gzip ~300 КБ) |
| `books.json` | обе книги: KPI (NAV, кэш, вложено, P&L, max gain), открытые позиции с отметкой, закрытые, журнал сделок, история NAV | ~50 КБ |
| `engine.json` | последний скан движка: кандидаты и отказы с причинами (72ч стабильность, edge, ann), хвост лога решений | ~30 КБ |
| `alerts.json` | аномалии за 3 дня | ~20 КБ |

## 3. Экран (mobile-first, iOS)

Нижняя панель вкладок: **Рынки · Сигналы · Книга A · Claude · Ещё**.

- **Рынки** — поиск по словам, чипы категорий, пресеты («Фавориты 0.85–0.99», «≤ 30 дней», «edge > 0»), сортировка
  (объём 24ч, edge, ann. доходность, дни), карточки: вопрос, событие, Yes bid/ask, фаворит и его цена, дни, объём, изменение за день,
  fair/edge движка. Тап → лист с деталями, ссылкой на polymarket.com и кнопками «Купить Yes / Продать Yes» (бумажно, книга A).
- **Сигналы** — кандидаты движка и отказы с причинами; аномалии (скачок, объём, слом фаворита, neg-risk сумма > 1).
- **Книга A / Claude** — герой-цифра NAV, KPI-ряд, спарклайн NAV, позиции (отметка, P&L, дни, доходность к погашению, годовых),
  закрытые, журнал. У Claude — тег core/explore и последние действия движка.
- **Ещё** — настройки (репозиторий, токен для команд с телефона), свежесть данных, правила движка, кнопка «Обновить сейчас».

Действия с телефона идут через `POST /repos/{owner}/{repo}/dispatches` (fine-grained PAT, право Contents: write). Ответ
появляется через 1–3 минуты в `meta.json.last_action`; страница опрашивает его после отправки.

## 4. PWA

`display: standalone`, `apple-mobile-web-app-capable`, `viewport-fit=cover` + safe-area, иконка 180/192/512.
Service worker: оболочка — cache-first с версией, `data/*.json` — network-first с откатом в кэш (последние данные видны офлайн).
Токен и настройки — в `localStorage` установленного приложения (у иконки на «Домой» своё хранилище, отдельное от Safari).

## 5. Миграция и что дальше

1. Текущие книги скопированы в `cloud/state/` (снимок 2026-09-27). После пуша облако — единственный источник истины:
   локальный `app.py` и `claude_cycle.cmd` нужно остановить, иначе книги разойдутся.
2. Калибровка (`engine/policy.calibrate` по `night_eval/cases.parquet`) пересчитывается локально раз в месяц и коммитится как JSON.
3. Дальше: пуш-уведомления (Web Push на iOS ≥ 16.4) о погашениях и сигналах; neg-risk арбитраж по полному списку исходов;
   внешние эталоны (FedWatch, Deribit) по `docs/ENGINE_DESIGN.md`.
